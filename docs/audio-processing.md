# Audio input foundation

The current product skills for Listening and Speaking are text-oriented. This module adds a local, dependency-free input-validation foundation; it does not silently change those skills into audio transcription services.

## Supported behavior

`open_ielts_strategy.audio.inspect_audio(data, filename, ...)` accepts in-memory bytes and validates WAV or MPEG Layer III (MP3) containers. It checks non-empty input, extension, size limit, basic codec/container structure, sample rate/channel constraints for WAV, frame presence for MP3, and positive/bounded duration. It returns format, byte size, duration, sample rate, channels, and frame count. Defaults are 25 MiB and 15 minutes; callers may supply stricter limits.

No file is written, no network is accessed, and no API or model is invoked. WAV parsing uses the Python standard library. MP3 duration is estimated from valid MPEG audio frame headers and is a structural estimate, not a guarantee of decodability or perceptual quality.

## CI acceptance

Synthetic WAV bytes and synthetic MP3 frames exercise success and failure paths. CI must not download audio, install model weights, invoke hosted transcription, or require an API key. Corrupt/truncated files, unsupported extensions, empty data, and configured size/duration limits must fail closed.

## Explicitly out of scope

This is not speech recognition, diarization, pronunciation assessment, noise reduction, audio quality scoring, or evidence of transcription accuracy. A future local ASR adapter (for example, an optional locally installed Whisper-compatible engine) must be isolated behind an interface and must not be a required CI dependency. Any transcript generated by a mock is a fixture, not a real transcription.
